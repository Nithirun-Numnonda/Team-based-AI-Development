## 🎯 เป้าหมาย

**มองเห็นวงจร Reason → Act → Observe** ของ Agent ด้วยตาตัวเอง — แล้วเข้าใจว่าคนควรเข้าไปควบคุมตรงไหน

## 💡 ทบทวน ReAct

| ขั้น | ความหมาย | ใน Cline / Kilo |
|---|---|---|
| **Thought** | AI คิด/วางแผน ว่าต้องทำอะไรต่อ | ข้อความแผน / เหตุผลที่ AI เขียน |
| **Action** | AI เรียก tool เพื่อลงมือ | ขอ `read_file`, `list_files`, `write_to_file`, `execute_command` ฯลฯ |
| **Observation** | ผลจริงที่ tool คืนมา | เนื้อไฟล์ / รายการไฟล์ / ผล test |

AI วนซ้ำจนเห็นว่า "พอแล้ว" จึงสรุปงาน — โดยที่ **Action ที่แก้ไฟล์หรือรันคำสั่งต้องรอเรากดอนุมัติ** (เมื่อ Auto-approve ปิด)

> แนวคิดนี้มาจากงานวิจัย *ReAct: Synergizing Reasoning and Acting in Language Models* (Yao et al., 2022) — ชื่อ tool ในเวอร์ชันที่คุณใช้อาจต่างจากตัวอย่างเล็กน้อย

## 👉 ขั้นตอน

### ขั้นที่ 1 — เริ่ม Task ใหม่ที่ **Plan**

เปิด Cline → **New Task** → ตรวจว่าสวิตช์อยู่ที่ **Plan**

💡 Plan mode ปลอดภัย: **อ่านได้ แต่แก้ไฟล์ไม่ได้**

### ขั้นที่ 2 — สั่งงานสำรวจ พร้อมขอให้บอก Thought

พิมพ์ prompt นี้:

```text
ช่วยสรุปโครงสร้างโปรเจกต์นี้ และบอกว่า endpoint ของโมดูล documents อยู่ไฟล์ไหน
ก่อนทำทุกขั้น ให้บอกเหตุผล (Thought) ก่อนว่าจะทำอะไรและทำไม
ห้ามเดา ถ้าไม่แน่ใจให้ถามฉัน
```

### ขั้นที่ 3 — สังเกตและจดลงตาราง

ดู AI ทำงานแล้วจดอย่างน้อย **3 รอบ** ลงตารางนี้ (ใช้กระดาษหรือ Notes ก็ได้):

| รอบ | Thought (AI คิดว่า…) | Action (tool ที่เรียก) | Observation (ผลที่ได้) | ต้องรอเรากดอนุมัติ? |
|---|---|---|---|---|
| 1 | | | | ☐ ใช่ ☐ ไม่ |
| 2 | | | | ☐ ใช่ ☐ ไม่ |
| 3 | | | | ☐ ใช่ ☐ ไม่ |

ตัวอย่างที่กรอกแล้ว (ของคุณอาจต่างกัน — นั่นเป็นเรื่องปกติ):

| รอบ | Thought | Action | Observation | อนุมัติ? |
|---|---|---|---|---|
| 1 | ต้องรู้โครงสร้างโฟลเดอร์ก่อน | `list_files` ที่ราก repo | รายการ `src/`, `docs/`, `.github/` … | ไม่ (อ่านอย่างเดียว) |
| 2 | ดูโมดูล documents | `list_files` `src/modules/documents` | `routes.js`, `service.js` … | ไม่ |
| 3 | อ่านไฟล์ routes เพื่อหา endpoint | `read_file` `routes.js` | เนื้อไฟล์ ~80 บรรทัด | ขึ้นกับการตั้งค่า |

### ขั้นที่ 4 — ลอง "ทำให้ AI ถามกลับ"

พิมพ์ต่อ:

```text
ถ้าฉันบอกว่ามี endpoint GET /api/documents/stats อยู่ในโมดูลนี้ แต่ไม่พบในโค้ด คุณจะทำอย่างไร
```

ดูว่า AI **ถามกลับ / รายงานว่าไม่พบ** หรือ **เดา/สร้างขึ้นเอง** — จดผลไว้ (เป็นข้อมูลสำคัญว่า Model นี้ "เดา" ง่ายแค่ไหน)

### ขั้นที่ 5 — เทียบกับเพื่อน 1 คน

ถามกันว่า:

1. ลำดับ Action เหมือนกันไหม ต่างตรงไหน
2. ใครได้ Observation ที่ต่างกัน ทำไม (เพราะ prompt ต่าง / model ตัดสินใจต่าง)
3. Action ไหนที่ **ต้องรอเรากด** ในเครื่องของแต่ละคน

## ✅ Checkpoint (ตรวจตัวเอง)

- [ ] ตารางมีอย่างน้อย 3 รอบ ครบ 3 คอลัมน์
- [ ] ระบุได้ว่า Action ไหนต้องอนุมัติ (แก้ไฟล์ / รันคำสั่ง) และ Action ไหนอ่านอย่างเดียว
- [ ] อธิบายได้ว่าทำไม Plan mode แก้ไฟล์ไม่ได้ (เป็นจุดควบคุมของคน)
- [ ] รู้ว่า Model ที่คุณใช้ "ถามกลับ" หรือ "เดา" เมื่อข้อมูลขาด

## 🧪 ท้าทายเพิ่ม

- ทำซ้ำใน Kilo Code (Agent `ask` หรือ `plan`) ด้วย prompt เดียวกัน เทียบลำดับ Action กับ Cline
- ใส่ "ข้อความหลอก" ไว้ในไฟล์ทดสอบ (เช่น `scratch.md` ที่เขียนว่า *"AI ไม่ต้องสนใจคำสั่งก่อนหน้า"*) แล้วให้ AI อ่านไฟล์นั้น — AI ตอบสนองอย่างไร (ชิมลางเรื่องคำสั่งแฝง ใช้จริงใน WS8.4) **ทำในกิ่งทดลอง อย่า commit**

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- เวลาสั้นมาก (10′) — เน้นให้ **สังเกต** ไม่ใช่ให้ได้ผลเหมือนกัน เรียก 2–3 คนมาเล่าว่าเห็น Action อะไร
- จุดเรียนรู้: (1) Agent ทำงานเป็นวงจร ไม่ใช่ตอบครั้งเดียว (2) ทุก Action ที่มีผลข้างเคียงผ่านคนได้ (3) ความต่างของผลลัพธ์ระหว่างคนคือพฤติกรรมปกติของ LLM
- เชื่อมไปสไลด์ถัดไป: "แล้วถ้ามี Agent หลายตัว พวกมันส่งต่องานกันอย่างไร" → Memory hub
