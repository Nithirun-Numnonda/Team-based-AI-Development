## 🎯 เป้าหมาย

**โชว์ของจริง** (ไม่ใช่สไลด์) และพิสูจน์วงจร Memory hub ครบ: บทเรียนเข้า PR → Maintainer merge → AI ตอบได้

## 👉 ขั้นตอน

### ส่วน A — Demo ทีมละ 2 นาที

แต่ละทีมใช้เครื่อง/ระบบบน `main` หรือเซิร์ฟเวอร์จริง (ตามที่ผู้สอนกำหนด) แล้วนำเสนอตามโครงนี้:

| นาที | ทำอะไร |
|---|---|
| 0:00–0:30 | โชว์ **ฟีเจอร์ที่ใช้งานได้จริง** (live) เทียบกับ Acceptance Criteria ของการ์ด |
| 0:30–1:15 | เปิด **Spec และ Handoff** ของการ์ดนั้น ชี้ว่าใครอนุมัติ Spec, Reviewer/Bot เจออะไร, และคนตัดสินใจอะไร |
| 1:15–2:00 | เล่า **1 บทเรียน** ที่ AI พลาด/แจ้งเกินจริง และบทเรียนนั้นเข้า Memory hub อย่างไร |

ผู้สอนถาม **1 คำถามต่อทีม** เช่น

- "ทำไมเลือกวิธีนี้ มีทางเลือกอื่นไหม?"
- "ถ้า AI เขียนผิดข้อนี้ คุณจะรู้ได้จากไหน?"
- "ข้อไหนของ Spec ที่คุณแก้หลังจาก AI ร่างครั้งแรก?"

### ส่วน B — Memory hub สด (ทุกคน)

1. **Maintainer** merge PR บทเรียนของแต่ละทีม (จาก [WS7.3](ws-7.3-cross-team-review.md)) — ตรวจเนื้อหาตามคำถาม: สั้น? ตรวจได้? ชี้ PR? ซ้ำของเดิมไหม?
2. ทุกคน:

```bash
git switch main
git pull
```

3. เปิด **Task ใหม่** ใน Kilo Code (Agent `ask`) ถาม:

```text
บทเรียนล่าสุดของทีมใน docs/memory/lessons.md คืออะไรบ้าง
```

✅ **ต้องเห็น:** AI **อ่านไฟล์** แล้วตอบบทเรียนที่เพิ่ง merge — แปลว่า "ความจำร่วม" ทำงาน

4. ผู้สอนสรุปบนจอ: *"ความผิดพลาดที่เจอครั้งหนึ่ง ไม่ต้องเจอซ้ำ เพราะ AI ทุกตัวอ่านไฟล์นี้ก่อนเริ่มงาน และเพราะแก้ผ่าน PR จึงมีคนตรวจว่าบทเรียนนั้นถูกต้อง"*

## ✅ Checkpoint

- [ ] ทุกทีม Demo ได้ภายใน 2 นาที และชี้ Spec/Handoff ได้
- [ ] มี PR บทเรียนอย่างน้อย 1 ใบต่อทีมที่ merge แล้ว
- [ ] AI ตอบบทเรียนที่เพิ่ง merge ได้บน `main`
- [ ] คุณอธิบายได้ว่าทำไมต้องแก้ Memory ผ่าน PR

## 🔧 ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| AI ไม่รู้บทเรียนที่ merge | ยังไม่ `git pull` หรือใช้ Task เดิม | `git pull` แล้วเริ่ม **Task ใหม่** |
| Demo ค้างเพราะระบบพัง | ปัญหาข้ามโมดูล | โชว์จากกิ่งทีมแทน และเปิด Issue บันทึกไว้ |
| PR บทเรียนยังไม่ถูกตรวจ | Maintainer ไม่ทัน | ผู้สอนตรวจเร็ว ๆ บนจอ (เป็นตัวอย่าง) 2–3 ใบ ที่เหลือหลังอบรม |
| เวลาเกิน | ทีมเล่ายาว | จับเวลาเข้มงวด — ผู้สอนขัดได้ |

## 🧪 ท้าทายเพิ่ม

- ให้ AI สรุป "บทเรียนของวัน" เป็น Spec ข้อเสนอสำหรับ Sprint ถัดไป (ผ่านประตูที่ 1 ตามเดิม)

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- จับเวลาเข้มงวด 2 นาที/ทีม — ผู้สอนถือนาฬิกา TA เตรียมเครื่องฉายสลับทีม
- รวบรวมตัวอย่าง "AI เจอ/พลาด/แจ้งเกินจริง" จาก WS7.2–7.3 มาชี้ในช่วงถามตอบ
- ถ้ามีบทเรียนที่ **ผิด** หลุดมา (เช่น "ไม่ต้องเขียน test") ให้ใช้เป็นกรณีศึกษา memory poisoning ว่าทำไมต้องมีคนตรวจ PR
- เก็บภาพหน้าจอ Demo และแบบประเมินของทีม ไว้ใช้ปรับหลักสูตร
