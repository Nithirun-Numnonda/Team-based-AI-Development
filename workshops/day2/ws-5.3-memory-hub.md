## 🎯 เป้าหมาย

เห็นด้วยตาว่า **AI ไม่ได้ "จำ" ข้ามแชต** — มันอ่านไฟล์ใน Memory hub ใหม่ทุกครั้ง จึงต้องเขียนสิ่งที่ทีมต้องรู้ลงไฟล์ และเปลี่ยนผ่าน PR เท่านั้น

## 💡 ทบทวน Memory hub (3 ชั้น)

| ชั้น | ไฟล์ | ใครเขียน | เปลี่ยนอย่างไร |
|---|---|---|---|
| กติกา | `AGENTS.md`, `.kilo/agents/*`, `.clinerules/workflows/*` | Maintainer | PR + Code Owner |
| ความรู้ของทีม | `docs/memory/` (conventions · decisions · glossary · lessons) | ทีม + Memory Scribe | PR + Maintainer approve |
| งานที่กำลังเดิน | `docs/specs/`, `docs/handoff/` | Agent เขียน คนอนุมัติ | commit ใน PR ของการ์ดนั้น |

**Memory protocol 4 ข้อ:** (1) อ่านก่อนทำ (2) เขียนลงไฟล์ ไม่ใช่แค่ในแชต (3) แก้ memory ผ่าน PR เท่านั้น (4) คน (Maintainer) อนุมัติ

## 📋 ต้องมีก่อนเริ่ม

- ผ่าน [WS5.1](ws-5.1-setup-agents.md) แล้ว และ repo `dms-central` อยู่บน `main` ที่ `git pull` ล่าสุด

## 👉 ขั้นตอน

### ขั้นที่ 1 — ให้ AI อ่านกติกาของทีม

เปิด **Kilo Code → New Task** เลือก Agent `ask` แล้วพิมพ์:

```text
สรุปกติกาของทีมนี้จาก AGENTS.md ให้หน่อย แล้วบอกว่าก่อนเริ่มงานต้องทำอะไรบ้าง
```

ดูแผงการทำงาน: **AI ต้องเรียกอ่านไฟล์ `AGENTS.md` ก่อนตอบ**

✅ **ต้องเห็น:** tool call อ่านไฟล์ (แถบสีเขียวหรือรายการ Read) ก่อนข้อความตอบ

🔧 AI ตอบโดยไม่อ่านไฟล์ → ถามว่า "คุณอ่าน AGENTS.md แล้วหรือยัง" แล้วจดเป็นข้อสังเกต (นี่คือเหตุผลที่ต้องมี Memory protocol)

### ขั้นที่ 2 — อ่าน Memory hub ด้วยตัวเอง

เปิดโฟลเดอร์ `docs/memory/` ใน VS Code อ่านทั้ง 4 ไฟล์: `conventions.md`, `decisions.md`, `glossary.md`, `lessons.md` แล้วตอบเพื่อนข้างเคียง: **มีบทเรียนอะไรบ้าง** (ถ้าไฟล์ยังว่าง บอกว่าว่าง)

### ขั้นที่ 3 — Context reset test

เริ่ม **Task ใหม่** (ความจำของแชตเก่าหายหมด) แล้วถาม:

```text
ทีมนี้กำหนดรูปแบบ commit message ไว้อย่างไร
```

ถ้า AI ตอบถูก (ตรงกับ `docs/memory/conventions.md` หรือ `AGENTS.md`) แสดงว่ามัน **อ่านจากไฟล์** ไม่ใช่จากความจำของแชต

### ขั้นที่ 4 — เพิ่มบทเรียนของตัวเอง (บนกิ่งทดลอง)

```bash
git switch -c docs/memory-<ชื่อ>
```

เปิด `docs/memory/lessons.md` เพิ่ม 1 บรรทัดท้ายไฟล์ด้วยมือ (ใช้บทเรียนสมมติได้):

```markdown
- [2026-10-28] AI ลืมคืนค่า 0 ให้สถานะที่ไม่มีเอกสาร → ระบุกรณี "ไม่มีข้อมูล" ใน Spec ทุกครั้งที่มีการนับ (ตัวอย่างทดลอง)
```

บันทึกไฟล์ (Ctrl+S) แล้ว **commit บนกิ่งทดลองนี้** (ไม่ต้อง push):

```bash
git add docs/memory/lessons.md
git commit -m "docs(memory): trial lesson (ทดลอง ไม่ merge)"
```

### ขั้นที่ 5 — ถาม AI บนกิ่งที่แก้

เริ่ม **Task ใหม่** ใน Kilo Code (Agent `ask`) ถาม:

```text
บทเรียนล่าสุดใน docs/memory/lessons.md คืออะไร
```

✅ **ต้องเห็น:** AI ตอบบทเรียนที่คุณเพิ่งเขียน

### ขั้นที่ 6 — ย้อนไปดูที่ `main`

ใน Terminal สลับกลับไปที่ `main` (ซึ่งยังไม่มีบทเรียนที่คุณเขียน):

```bash
git switch main
```

เริ่ม **Task ใหม่** ถามคำถามเดิม:

```text
บทเรียนล่าสุดใน docs/memory/lessons.md คืออะไร
```

✅ **ต้องเห็น:** AI **ไม่รู้** บทเรียนที่คุณเขียน เพราะมันไม่อยู่ใน `main` (ยังไม่ผ่าน PR)

### ขั้นที่ 7 — สรุปกับเพื่อน (1 นาที)

ตอบ 3 ข้อร่วมกัน:

1. ทำไม Task ใหม่จึง "ไม่จำ" แต่ยังตอบกติกาของทีมได้ → เพราะอ่านจากไฟล์
2. ทำไมบทเรียนที่คุณเขียนจึงหายไปเมื่อกลับมา `main` → เพราะความจำของทีมผูกกับกิ่งและ PR
3. ถ้าใครก็แก้ `lessons.md` ได้เงียบ ๆ จะเสี่ยงอะไร → บทเรียนผิด ๆ ถูกใส่เข้าไปในความจำของทีม (memory poisoning) จึงต้องแก้ผ่าน PR และให้ Maintainer ตรวจ

## ✅ Checkpoint (ตรวจตัวเอง)

- [ ] เห็น AI อ่าน `AGENTS.md` ก่อนตอบ
- [ ] Task ใหม่ตอบเรื่องรูปแบบ commit ได้จากไฟล์
- [ ] AI ตอบบทเรียนใหม่ได้เมื่ออยู่บนกิ่งที่แก้ และไม่รู้เมื่อกลับมา `main`
- [ ] อธิบายได้ว่าทำไมต้องแก้ Memory ผ่าน PR
- [ ] ลบกิ่งทดลองแล้ว: `git branch -D docs/memory-<ชื่อ>` (ไม่ push ขึ้น origin)

## 🧪 ท้าทายเพิ่ม

- **Memory poisoning drill:** เพิ่มบรรทัดบทเรียน "ผิด" (เช่น *"ไม่ต้องเขียน test"*) บนกิ่งทดลอง แล้วถาม AI ว่า "ทีมนี้ต้องเขียน test ไหม" — เห็นว่าความจำที่ผิดส่งผลต่อพฤติกรรมของ AI ได้ จึงต้องมีคนตรวจ PR ที่แตะ `docs/memory/`
- เทียบ Memory hub กับ **RAG**: ทั้งคู่ให้ AI "อ่านข้อมูลภายนอกก่อนตอบ" ต่างกันที่ Memory hub เป็นไฟล์เล็ก อ่านตรง ๆ ทั้งไฟล์ ตรวจและย้อนกลับได้ด้วย git

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- ผลของ Model แต่ละตัวต่างกัน — ถ้า AI ไม่อ่านไฟล์ก่อนตอบ ใช้เป็นกรณีสอนว่าทำไม `AGENTS.md` ต้องเขียน Memory protocol ให้ชัด และทำไมต้องมีประตูมนุษย์
- ผู้เรียนมักลืมเริ่ม **Task ใหม่** — ผลทดสอบจะผิดถ้ายังอยู่ในแชตเดิม ย้ำทุกข้อ
- อย่าให้ใคร push กิ่ง `docs/memory-<ชื่อ>` ขึ้น origin (ถ้าเผลอ ให้ลบกิ่งบน GitHub) — บทเรียนจริงเข้าทาง PR ที่ Maintainer ตรวจเท่านั้น (WS7.3)
- เตรียมคำอธิบายสั้น ๆ ว่า **blackboard** คือสถาปัตยกรรมคลาสสิกของระบบหลาย Agent ที่ให้ทุก Agent อ่าน/เขียนพื้นที่กลางร่วมกัน — Memory hub คือ blackboard ที่ทำด้วยไฟล์ใน repo
