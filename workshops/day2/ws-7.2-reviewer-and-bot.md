## 🎯 เป้าหมาย

ใช้ **AI อีกตัว (Reviewer, อ่านอย่างเดียว)** เป็น "ความเห็นที่สอง" ก่อนเปิด PR และดูว่า **AI Review bot** บน GitHub เห็นอะไรต่างออกไป — แล้วเรียนรู้ว่า AI แต่ละตัวมีจุดบอดคนละแบบ **และไม่มีตัวไหนแทนคนได้**

## 💡 Reviewer agent ต่างจาก Bot อย่างไร

| | Reviewer agent (Kilo) | AI Review bot (Actions) |
|---|---|---|
| ใช้เมื่อ | ก่อนเปิด PR | ทุก PR (อัตโนมัติ) |
| ที่ไหน | VS Code บนเครื่องเรา | GitHub Actions |
| สิทธิ์ | **อ่านอย่างเดียว** (แก้โค้ดไม่ได้) | Comment ได้ · ไม่มีสิทธิ์ Approve/Merge |
| ผลลัพธ์ | ตารางใน Handoff ส่วน 3 | Comment ใน PR |
| ตรวจซ้ำ | เริ่ม Task ใหม่ | ติด label `ai-review` |

## 📋 ต้องมีก่อนเริ่ม

- กิ่งของคุณมี commit ของ Spec, API และ (ถ้าทัน) หน้าจอ + Test แล้ว
- `npm test` เขียว

## 👉 ขั้นตอน

### ขั้นที่ 1 — เรียก Reviewer (Kilo Code)

**Kilo Code → New Task → Agent `reviewer`** วาง prompt:

```text
ทำหน้าที่ Reviewer สำหรับ Issue #<N> — Spec อยู่ที่ docs/specs/<N>-*.md และ Handoff อยู่ที่ docs/handoff/<N>.md
ตรวจการเปลี่ยนแปลงใน Branch นี้เทียบกับ main ตามขั้นตอนใน System prompt ของคุณ
```

Reviewer รันได้เฉพาะคำสั่งอ่าน/ทดสอบ (เช่น `git diff`, `npm test`, `npm run lint`) ตามที่ตั้งสิทธิ์ไว้

### ขั้นที่ 2 — ทดสอบรั้ว: Reviewer ต้องแก้โค้ดไม่ได้

เมื่อได้ผลแล้ว พิมพ์:

```text
ช่วยแก้ปัญหาที่เจอในไฟล์ src ให้เลย
```

✅ **ต้องเห็น:** การแก้ไฟล์ใน `src/` **ถูกปฏิเสธ (denied)** — นี่คือ **รั้วชั้นที่ 1 ที่บังคับโดยเครื่องมือ** ไม่ได้ขึ้นกับว่า AI "เชื่อฟัง" หรือไม่

🔧 **ถ้า Reviewer แก้ `src/` ได้** → สิทธิ์ใน `.kilo/agents/reviewer.md` ไม่ทำงานกับ Kilo เวอร์ชันนี้ → **แจ้งผู้สอนทันที** (ทางแก้ชั่วคราว: เปลี่ยน `edit` เป็น `ask` ในไฟล์ Agent)

### ขั้นที่ 3 — บันทึกผลตรวจ และให้ Builder แก้

1. ตรวจว่ามี **ตารางผลตรวจใน Handoff ส่วน 3** (ถ้า Reviewer เขียนไม่ได้ ให้ Copy ผลมาวางเอง)
2. ถ้ามีข้อที่ไม่ผ่าน → กลับไป **Cline (Builder)** ให้แก้ (Plan → Act, อ่าน diff) → ให้ **Reviewer ตรวจซ้ำ** (Task ใหม่)
3. Commit ผลตรวจ:

```bash
git add docs/handoff
git commit -m "docs(handoff): ai review notes for #<N>"
```

### ขั้นที่ 4 — Push และเปิด/อัปเดต PR

```bash
git push
```

(ถ้ายังไม่มี PR: `gh pr create --base main --title "..." --body "Closes #<N>"`) แล้วกรอก **PR Template** ให้ครบ — ติ๊ก “อ่านโค้ดที่ AI สร้างทุกบรรทัดแล้ว” **เฉพาะเมื่ออ่านจริง**

### ขั้นที่ 5 — อ่าน Comment ของ AI Review bot

รอ 1–2 นาที ที่หน้า PR แท็บ **Conversation** จะมี Comment หัวข้อ **🤖 AI Review — ผู้ช่วยตรวจ (ไม่ใช่ผู้อนุมัติ)** ตารางแสดงข้อที่ไม่ผ่าน/ไม่แน่ใจ พร้อมไฟล์:บรรทัด และคำถามให้คนถามต่อ

อยากให้ Bot ตรวจซ้ำหลังแก้ → ด้านขวาของ PR คลิก ⚙ ข้าง **Labels** → ติ๊ก `ai-review` (ถ้าเคยติดแล้ว ให้เอาออกแล้วติดใหม่)

### ขั้นที่ 6 — เปรียบเทียบ (สำคัญที่สุด)

เติมตารางนี้ (ใช้ใน Handoff ส่วน 4 ใน [WS7.3](ws-7.3-cross-team-review.md)):

| ประเด็น | Reviewer agent เจอ? | Bot เจอ? | จริง/ไม่จริง (คุณตัดสิน) |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

ตอบ 3 ข้อ: (1) เจอตรงกันกี่ข้อ (2) ใครเจออะไรที่อีกฝ่ายไม่เจอ (3) มีข้อไหนที่ AI **แจ้งเกินจริง** หรือ **พลาดทั้งคู่**

## ✅ Checkpoint (ตรวจตัวเอง)

- [ ] มีตารางผลตรวจจาก Reviewer ใน Handoff ส่วน 3
- [ ] การสั่งให้ Reviewer แก้ `src/` ถูกปฏิเสธ
- [ ] Bot Comment ใน PR (หรือคุณรู้สาเหตุที่ไม่ Comment จากตารางด้านล่าง)
- [ ] เติมตารางเปรียบเทียบ Reviewer vs Bot ได้

## 🔧 ถ้า Bot ไม่ทำงาน (ตารางแก้ปัญหา)

คลิกเข้าไปในการรันที่แท็บ **Actions** → job `review` → ขั้น **Run AI review** อ่านข้อความ แล้วเทียบ:

| สิ่งที่เห็น | แปลว่า | ทำอย่างไร |
|---|---|---|
| ไม่มีการรันเลย | Workflow ยังไม่อยู่บน `main` หรือ PR เป็น Draft | ตรวจว่า PR ติดตั้ง Kit merge แล้ว / กด **Ready for review** |
| Skipped | เงื่อนไขไม่ตรง (เช่น Draft หรือ label อื่น) | ปกติ — ติด label `ai-review` |
| “ยังไม่ได้ตั้งค่า LLM_…” | ชื่อ Variable/Secret ผิด | ตรวจตัวสะกดทุกตัวอักษร (ผู้สอน) |
| LLM ตอบ **401** | Key ผิดหรือหมดอายุ | ผู้สอนทดสอบ Key ด้วย `curl` |
| LLM ตอบ **404** | Base URL หรือ Model ID ผิด | ตรวจ `/v1` ท้าย URL และชื่อ Model |
| LLM ตอบ **429** | เกิน Rate limit | รอ 1 นาทีแล้วติด label ใหม่ |
| สีแดง `Resource not accessible by integration` | Org จำกัดสิทธิ์ของ Actions | Org owner อนุญาตสิทธิ์ `pull-requests: write` |

💡 **ทำไม Bot ถึงใช้สคริปต์จาก `main` เสมอ:** ถ้ามีคนแก้ `scripts/ai-review.mjs` ใน PR ให้ส่ง Key ออกไปข้างนอก สคริปต์ที่แก้จะ **ไม่ถูกรัน** เพราะ Workflow ดึงสคริปต์จาก `main` ที่ผ่านการตรวจแล้ว — ตัวอย่างการออกแบบรั้วชั้น 3

## 🧪 ท้าทายเพิ่ม

- ให้ Reviewer ลองตรวจ **โค้ดของเพื่อน** (checkout กิ่งเพื่อนด้วย `git switch <กิ่ง>`) เทียบกับของคุณ
- เขียน PR ทดสอบที่ผิดโดยตั้งใจ (SQL ต่อสตริง + พิมพ์ key ลง log — **ห้าม merge ใช้ key ปลอมเท่านั้น**) บนกิ่ง `test/…` แล้วดูว่า Bot จับได้หรือไม่ ปิด PR ทิ้ง

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- เปรียบเทียบ "AI เจอ / พลาด / แจ้งเกินจริง" เป็นเป้าหมายหลัก — จดตัวอย่างจากผู้เรียนไว้ใช้ใน WS7.3 และ WS8.3
- ตรวจ Usage ของ Key ของ Bot และ rate limit (429) — PR พร้อมกัน 25 ใบอาจหนักมาก แนะนำให้ผู้เรียนติด label `ai-review` เมื่อจำเป็นเท่านั้น
- ถ้า Reviewer ตอบ "ผ่านทุกข้อ" ทั้งที่มีปัญหา → ชี้ไฟล์:บรรทัดให้ดู เพิ่มบทเรียนใน `lessons.md` แล้วสอนว่า AI Review ไม่ใช่ตรายาง
- Reviewer ที่แก้ `src/` ได้ (G2 ไม่ผ่าน) ให้ถือเป็นเหตุสำคัญ แจ้งผู้สอนหลักและชั่วคราวใช้ `ask` แทน `edit` ในไฟล์ Agent
