## 🎯 เป้าหมาย

ให้ AI **อ่านโจทย์และ Memory hub แล้วเขียน "แบบ" ของงาน (Spec)** ก่อนเขียนโค้ด

💡 **ทำไมต้อง Spec:** Spec คือจุดที่แก้ทางได้ถูกที่สุด — แก้ Spec 2 บรรทัดง่ายกว่าแก้โค้ด 200 บรรทัดที่ AI เขียนผิดทาง และ Spec ยังเป็นเอกสารที่คนในหน่วยงานอื่นอ่านเข้าใจ

## 📋 ต้องมีก่อนเริ่ม

- ผ่าน WS5.1–5.4 (`npm test` ผ่านบนเครื่อง, Auto-approve ปิด, เห็น Agent `designer`)
- ทีมมีการ์ดของโมดูลใน Board ของ `dms-central` (จาก WS4.4 / Backlog ที่ผู้สอนเตรียม)
- ทีมตกลงแล้วว่า **ใครหยิบการ์ดใบไหน** (ห้ามซ้ำกัน)

## 👉 ขั้นตอน

### ขั้นที่ 1 — หยิบการ์ด

1. เปิด Issue ของการ์ดที่เลือก → ดู **เลข Issue** (หลังชื่อ เช่น `#12`) ในเอกสารนี้ใช้ `<N>`
2. **Assign yourself** (บอกทุกคนว่าการ์ดนี้มีเจ้าของแล้ว) แล้วย้ายการ์ดเป็น **In Progress**
3. **คัดลอกเนื้อหา Issue ทั้งหมด** (รวม Acceptance Criteria) ไว้วางให้ Designer

### ขั้นที่ 2 — สร้างกิ่ง

```bash
git switch main
git pull
git switch -c feat/<N>-<ชื่อสั้น>
```

ตัวอย่าง: `feat/12-search-by-tag`

### ขั้นที่ 3 — ให้ Designer (Kilo Code) ออกแบบ

1. คลิกไอคอน **Kilo Code** → **New Task**
2. คลิกตัวเลือก **Agent** → เลือก **designer**
3. วาง prompt นี้แล้วกด Enter:

```text
ทำหน้าที่ Designer สำหรับ Issue #<N> ของ Repository นี้
เนื้อหา Issue:
---
<วางเนื้อหา Issue ที่คัดลอกมา>
---
ทำตามขั้นตอนใน System prompt ของคุณ: อ่าน AGENTS.md และ docs/memory ก่อน แล้วสร้าง Spec และ Handoff ส่วนที่ 1
```

4. ถ้า Kilo ถามขออนุญาตเขียนไฟล์ใน `docs/specs/` หรือ `docs/handoff/` → กด **อนุญาต (Approve/Allow)** (เขียนไฟล์ในสองโฟลเดอร์นี้ได้เท่านั้น)

### ขั้นที่ 4 — สังเกตสิ่งที่ Designer ทำ

✅ **ต้องเห็น (จดลงแบบบันทึก):**

- [ ] AI เรียกอ่าน `AGENTS.md` และไฟล์ใน `docs/memory/` **ก่อน** — แปลว่า Memory protocol ทำงาน
- [ ] มีไฟล์ใหม่ 2 ไฟล์: `docs/specs/<N>-….md` และ `docs/handoff/<N>.md`
- [ ] **ไม่มี** การเขียนไฟล์ใน `src/` หรือ `test/` (ถ้า AI พยายามแล้วถูกปฏิเสธ → ถูกต้อง นี่คือรั้วชั้นที่ 1)
- [ ] ถ้า Issue ต้องการ endpoint/ข้อมูลที่ **ไม่อยู่ใน `openapi.yaml`** — AI **ถามกลับ** แทนที่จะเดาเอง

### ขั้นที่ 5 — ตอบคำถามและให้ปรับ Spec

ถ้า AI ถามกลับ ให้ตอบในช่องแชต เช่น:

```text
Endpoint นี้ยังไม่อยู่ใน openapi.yaml — อนุญาตให้เพิ่มได้ ในฐานะเจ้าของโมดูล ช่วยปรับ Spec ให้สอดคล้อง
```

> ถ้าการเปลี่ยน **สัญญากลาง** (`openapi.yaml`) กระทบทีมอื่น → ถามผู้ดูแล (Maintainer) ก่อน อย่าตัดสินเองคนเดียว

### ขั้นที่ 6 — อ่านผลลัพธ์ (ก่อนส่งต่อ WS6.2)

ใน Explorer ไฟล์ใหม่มีตัว **U (Untracked)** สีเขียว — คลิกเปิดอ่าน Spec **ทุกหัวข้อ** โดยเฉพาะ **กรณีทดสอบ** และ **ไฟล์ที่จะแตะ**

## ✅ Checkpoint (ตรวจตัวเอง)

- [ ] มี Spec + Handoff ของการ์ดคุณ
- [ ] เห็น tool call อ่าน AGENTS.md / docs/memory ก่อนเขียน
- [ ] ไม่มีไฟล์ใน `src/` ถูกสร้างโดย Designer
- [ ] คุณรู้ว่า Spec ข้อไหนที่คุณจะตรวจละเอียดที่สุดในขั้นถัดไป

## 🔧 ถ้าไม่เป็นแบบนี้

| อาการ | วิธีแก้ |
|---|---|
| AI ไม่ถามกลับ แต่ออกแบบ endpoint เองเลย | **จดไว้** (ข้อมูลสำคัญว่า Model นี้ "เดา" ง่าย) แล้วถามมันว่า "Endpoint นี้อยู่ใน openapi.yaml หรือไม่" |
| AI พยายามสร้างไฟล์ใน `src/` แล้วถูกปฏิเสธ | ถูกต้องแล้ว — นี่คือรั้วที่ทำงาน ไม่ต้องแก้อะไร |
| AI ไม่อ่าน memory เลย | ตรวจว่า `AGENTS.md` ในกิ่งของคุณมีหัวข้อ **Memory protocol** (อาจ clone มาก่อน Kit ถูก merge → `git pull` ก่อนสร้างกิ่ง) |
| ไม่เห็น Agent `designer` | ดู WS5.1 ขั้นที่ 6 |
| Spec กว้างเกินการ์ด | บอก AI: "ทำเฉพาะขอบเขตตาม Acceptance Criteria ของ Issue นี้ ข้อไหนเกินให้ใส่ใน 'ไม่ทำ'" |

## 🧪 ท้าทายเพิ่ม

- ขอให้ Designer เพิ่มหัวข้อ **ความเสี่ยง** ใน Spec 3 ข้อ แล้วดูว่าสมเหตุสมผลไหม
- เปรียบเทียบ Spec ของคุณกับของเพื่อนที่ใช้การ์ดคล้ายกัน — ต่างกันตรงไหน (และ Model ตัดสินใจต่างกันเพราะอะไร)

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- ตรวจให้ **ทุกคนใช้เลข Issue ต่างกัน** — ถ้าสองคนใช้เลขเดียวในกิ่งเดียว จะ conflict ที่ไฟล์ Spec/Handoff
- ถ้า Model ไม่อ่าน memory เอง ใช้เป็นตัวอย่างสอน (ไม่ต้องแก้ทันที) และจด "ข้อสังเกต" ลงแบบบันทึก Drill
- ชั่วโมงนี้ TA ควรเดินดูว่า (1) ใครสั่ง Designer เขียนโค้ด (2) ใครเปิด Auto-approve (3) ใครคัดลอก Issue ไม่ครบ AC
- แม่แบบ Spec (`docs/specs/_template.md` หรือเทียบเท่า) มาจาก Kit — ตรวจชื่อหัวข้อให้ตรงกับที่สอนในสไลด์ก่อนวันจริง
