## 🎯 เป้าหมาย

**คนตัดสินว่า "จะสร้างอะไร"** ก่อนที่ AI จะเขียนโค้ดยาว ๆ — ถ้าปล่อยให้ AI อนุมัติเอง ประตูนี้ก็ไม่มีความหมาย

## 👉 ขั้นตอน

### ขั้นที่ 1 — อ่าน Spec ด้วย 5 คำถาม

เปิดไฟล์ `docs/specs/<N>-….md` อ่านแล้วตอบ:

| # | คำถาม | ดูที่ |
|---|---|---|
| 1 | ครอบคลุม **Acceptance Criteria ทุกข้อ** ของ Issue ไหม | เทียบกับ Issue |
| 2 | **ไฟล์ที่จะแตะ** อยู่ในขอบเขตของโมดูลเราไหม (ไม่ล้ำโมดูลอื่น) | หัวข้อ "ไฟล์ที่จะแตะ" |
| 3 | **กรณีทดสอบ** ครบไหม (ปกติ + กรณีขอบ + ผิดพลาด) | หัวข้อ "กรณีทดสอบ" |
| 4 | **สิทธิ์** ถูกไหม (ใครเรียกได้ ใครไม่ได้ / ไม่มี Token คืนอะไร) | หัวข้อ "สิทธิ์" |
| 5 | **คำถามที่ยังเปิด** ตอบหมดแล้วหรือยัง (ไม่เหลือข้อให้ AI เดา) | หัวข้อ "คำถามที่ยังเปิด" |

### ขั้นที่ 2 — ข้อไหนไม่ผ่าน ให้ Designer แก้

พิมพ์บอก Designer (ใน Task เดิมของ Kilo) เช่น:

```text
กรณีทดสอบยังไม่มีกรณี "ไม่มี Token" ช่วยเพิ่ม และระบุผลที่คาดว่า 401
```

แล้วอ่าน Spec ใหม่อีกรอบจนผ่านทั้ง 5 ข้อ

### ขั้นที่ 3 — ติ๊กอนุมัติ **ด้วยมือของคุณเอง**

เปิด `docs/handoff/<N>.md` ที่ส่วน **อนุมัติ Spec** แล้ว **พิมพ์เอง** เปลี่ยน `[ ]` เป็น `[x]` พร้อม username และวันที่ เช่น

```markdown
- [x] อนุมัติ Spec โดย @<username> เมื่อ 2026-10-28
```

(รูปแบบบรรทัดตามแม่แบบ Handoff ของ Kit) กด **Ctrl+S**

> ⚠️ **ห้ามสั่ง AI ติ๊กแทน** — นี่คือ "ลายเซ็น" ของคน

### ขั้นที่ 4 — Commit Spec แยกก่อนเขียนโค้ด

```bash
git add docs/specs docs/handoff
git commit -m "docs(spec): <เรื่อง> for #<N>"
git log --oneline -3
```

✅ **ต้องเห็น:** commit สำเร็จ "2 files changed" และเป็น **commit แรกของกิ่ง**

💡 **ทำไม commit Spec แยก:** ใน PR ทุกคนจะเห็นว่า commit แรกคือ Spec — เป็นหลักฐานว่า "ออกแบบก่อนลงมือ" ซึ่ง TA และผู้ตรวจใช้เป็นหนึ่งใน 4 สัญญาณของ Flow ที่ถูกต้อง

## ✅ Checkpoint (ตรวจตัวเอง)

- [ ] ตอบได้ครบ 5 คำถาม และ Spec ผ่านทั้ง 5 ข้อ
- [ ] Handoff ส่วน 1 มี `[x]` + username + วันที่ **ที่คุณพิมพ์เอง**
- [ ] commit แรกของกิ่งคือ `docs(spec): …`

## 🔧 ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ไม่เห็นบรรทัดอนุมัติใน Handoff | แม่แบบต่างจากที่เขียน | หา checkbox ในส่วนที่ 1 (Design) แล้วใส่ตามรูปแบบเดิม |
| commit แล้วมีไฟล์อื่นติดมาด้วย | ใช้ `git add -A` | `git restore --staged .` แล้ว add เฉพาะ `docs/specs docs/handoff` |
| Designer แก้ Spec ทับหลังติ๊กแล้ว | สั่งเพิ่มหลังอนุมัติ | ถือว่า Spec เปลี่ยน → อ่านอีกรอบแล้วติ๊กใหม่ |

## 🧪 ท้าทายเพิ่ม

- สลับ Spec กับเพื่อนในทีมและตรวจแบบ 5 คำถาม — ได้เจอจุดที่ตัวเองมองข้ามไหม
- เขียนคำถามที่ 6 ที่ทีมคุณอยากเพิ่ม (เช่น "กระทบข้อมูลเก่าไหม")

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- สุ่มถามผู้เรียน: "กรณีทดสอบข้อไหนสำคัญที่สุด เพราะอะไร" — คนที่ไม่ได้อ่านจะตอบไม่ได้
- ตรวจ **commit แรกของกิ่ง** ทุกคน (เป็นหลักฐานที่ TA ใช้ตรวจ) และตรวจว่าลายเซ็นไม่ได้มาจาก AI (ดูประวัติ Task ใน Kilo ถ้าสงสัย)
- เวลาสั้น (10′) — ถ้าผู้เรียนต้องแก้ Spec หลายรอบ ให้ทีมช่วยกันตรวจแทนที่จะรอ
