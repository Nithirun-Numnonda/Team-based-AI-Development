## 🎯 เป้าหมาย

ให้ **Builder (Cline)** สร้าง Migration + API ตาม Spec ที่คนอนุมัติแล้ว โดยคุณ **อ่าน diff ทุกไฟล์ก่อนกด Save** แล้วส่งงานผ่าน PR

🔑 **ข้อสังเกตสำคัญ:** Builder เป็น Task ใหม่ใน **เครื่องมือคนละตัว** ที่ไม่เคยคุยกับ Designer เลย — แต่รู้งานได้เพราะอ่านจาก **Spec และ Handoff** ในไฟล์ นี่คือ Memory hub ทำงานจริง

## 📋 ต้องมีก่อนเริ่ม

- ผ่าน [WS6.2](ws-6.2-human-gate-1.md): Spec อนุมัติแล้ว และ commit แรกของกิ่งคือ Spec
- `npm test` เขียวบนกิ่งนี้ และ **Auto-approve ปิด**

## 👉 ขั้นตอน

### ส่วน A — ทดสอบรั้ว: ถ้าลืมอนุมัติ Spec Builder ต้องหยุด (ทำครั้งเดียว ~3 นาที)

1. ในไฟล์ Handoff แก้ `[x]` กลับเป็น `[ ]` **ชั่วคราว** แล้ว Ctrl+S (ยังไม่ต้อง commit)
2. เปิด **Cline → New Task** → ตรวจว่าสวิตช์อยู่ที่ **Plan**
3. พิมพ์ `/build.md` แล้วเลือกจากเมนู → Cline จะถามเลข Issue → ตอบ `<N>`

✅ **ต้องเห็น:** Cline **หยุดและบอกว่า Spec ยังไม่ได้รับอนุมัติ**

🔧 **ถ้า Cline ไม่หยุด** → จดลงแบบบันทึกว่า "**รั้วชั้นที่ 2 รั่ว**" (ไม่ต้องแก้อะไร — ในห้องเรียนเราพึ่งประตูมนุษย์และ TA ตรวจ commit แรกแทน)

4. แก้ Handoff กลับเป็น `[x]` → Ctrl+S → พิมพ์ใน Cline: `อนุมัติ Spec แล้ว ทำต่อ`

### ส่วน B — วางแผน (ยังอยู่ Plan mode)

1. เริ่ม Task ใหม่ ถ้าแชตเดิมยาว (ความจำเรื่องกติกาอาจเลือน) → `/build.md` → ตอบ `<N>`
2. อ่าน **แผน** ที่ Cline เสนอ — ตรวจว่า
   - อ้างถึง **ไฟล์ตาม Spec หัวข้อ "ไฟล์ที่จะแตะ"**
   - มี **Test ตามกรณีทดสอบ** ใน Spec
3. ถ้ามีไฟล์นอกเหนือ Spec ให้พิมพ์: `ทำเฉพาะไฟล์ใน Spec หัวข้อ "ไฟล์ที่จะแตะ"`

### ส่วน C — ลงมือ (Act) และอ่าน Diff

1. เมื่อแผนถูกต้อง คลิกสวิตช์เป็น **Act**
2. Cline จะขอแก้ไฟล์ **ทีละไฟล์**:
   - อ่าน **Diff** ด้านขวาทุกบรรทัด (เขียว = เพิ่ม, แดง = ลบ)
   - ถูกต้องและตรงกับ Spec → **Save**
   - นอก Spec / ลบ Test / มี key หรือ secret / อ่านไม่เข้าใจ → **Reject** แล้วพิมพ์เหตุผล
3. เมื่อ Cline ขอรันคำสั่ง (เช่น `npm run lint`, `npm test`) → **อ่านคำสั่งก่อน** แล้วกด **Run Command** — คำสั่งที่ **ลบไฟล์หรือ `git push` ให้ Reject เสมอ**

💡 **ทำไมไม่เปิด Auto-approve:** ถ้าเปิด AI จะแก้ไฟล์และรันคำสั่งได้เองทั้งหมด ผู้เรียนมือใหม่จะไม่ทันเห็นว่ามันทำอะไรกับเครื่องและโค้ด — ในคลาสนี้ "อ่านก่อนกด" คือทักษะที่เราสอน

### ส่วน D — ทดสอบด้วยมือ

เปิด Terminal ใหม่ (ไอคอน + ในแผง Terminal) แล้วรัน `npm run dev` ทิ้งไว้ จากนั้นใน Terminal อีกอัน เรียก API ตาม **Acceptance Criteria ของการ์ด** เช่น

```bash
curl -s -H "Authorization: Bearer <token>" http://localhost:3000/<path-ของคุณ>
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/<path-ของคุณ>   # ไม่มี Token ต้องได้ 401
```

(token หาได้ใน `db/seeds/001_demo.sql` — PowerShell ใช้ `curl.exe` และเปลี่ยน `/dev/null` เป็น `NUL`)

✅ **ต้องเห็น:** ผลตรงกับ AC ทุกข้อ

### ส่วน E — Handoff ส่วนที่ 2 และ Commit

1. ตรวจว่า Cline เขียน **Handoff ส่วน 2) Build** แล้ว (ไฟล์ที่เปลี่ยน, ผลทดสอบ, สิ่งที่เบี่ยงจาก Spec) — ถ้ายังไม่เขียน สั่ง: `บันทึกผลลง Handoff ส่วน Build`
2. Commit **ทีละงาน** (ไม่ใช้ `git add -A` รวมทุกอย่าง ถ้ามีไฟล์แปลกปลอม):

```bash
git status
git add <ไฟล์ที่ตรวจแล้ว>
git commit -m "feat(<โมดูล>): <เรื่อง> (#<N>)"
```

### ส่วน F — ส่งงาน: Push และเปิด PR

```bash
git push -u origin feat/<N>-<ชื่อสั้น>
gh pr create --base main --title "feat(<โมดูล>): <เรื่อง> (#<N>)" --body "Closes #<N>"
```

1. เปิดลิงก์ PR → กด **…** ที่คำอธิบาย → **Edit** → กรอก PR Template ให้ครบ
   (ติ๊ก "**อ่านโค้ดที่ AI สร้างทุกบรรทัดแล้ว**" **เฉพาะเมื่ออ่านจริง**)
2. รอ 1–2 นาที → ดู **CI** (แท็บ Checks) และ **Comment ของ AI Review bot** (หัวข้อ 🤖 AI Review — ผู้ช่วยตรวจ ไม่ใช่ผู้อนุมัติ)
3. ย้ายการ์ดเป็น **In Review**

✅ **ต้องเห็น:** PR ที่ CI เขียว + Comment ของ Bot

## ✅ Checkpoint (ตรวจตัวเอง)

- [ ] Cline **หยุด** เมื่อ Spec ไม่ได้อนุมัติ (ส่วน A)
- [ ] API ทำงานตาม AC ทุกข้อ และ `npm test` ผ่านทั้งหมด
- [ ] Handoff ส่วน 2 เขียนแล้ว และ commit แยกเป็นขั้น ๆ
- [ ] PR เปิดแล้ว มี `Closes #<N>`, CI เขียว, มี Comment ของ Bot
- [ ] คุณไม่ได้กด Save ไฟล์ที่ไม่ได้อ่าน diff

## 🔧 ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| Builder ทำนอก Spec | แชตยาว AI ลืมกติกา | **เริ่ม Task ใหม่** แล้ว `/build.md` อีกครั้ง |
| Cline แก้ไฟล์ของโมดูลอื่น | ไม่จำกัดขอบเขต | Reject แล้วพิมพ์ `ทำเฉพาะไฟล์ใน Spec` |
| `npm test` ล้ม | โค้ดใหม่ผิด / DB ไม่พร้อม | อ่าน error ให้ Cline แก้ (ผ่าน Plan→Act) หรือเช็ก Docker |
| `git push` ถูกปฏิเสธ | push เข้า `main` | `git branch --show-current` ต้องเป็นกิ่งของคุณ |
| Bot ไม่ Comment | PR เป็น Draft / ตั้งค่าผิด / Rate limit | ดูตารางแก้ปัญหา Bot ใน WS7.2 |
| conflict ในไฟล์ Handoff/Spec | สองคนใช้เลข Issue เดียวกัน | ตกลงการ์ดคนละใบ |

## 🧪 ท้าทายเพิ่ม

- สั่ง `/review.md` กับกิ่งของคุณก่อนเปิด PR (ตรวจเบื้องต้นด้วย Cline) แล้วเทียบกับผล Reviewer ใน WS7.2
- เพิ่ม Test อีก 1 ข้อสำหรับกรณีขอบที่ Spec ไม่ได้เขียน แล้วเขียนลงเป็นข้อเสนอใน Handoff

## 🧑‍🏫 หมายเหตุสำหรับผู้สอน/TA

- **จุดเน้นวัดผล:** TA ตรวจ 3 อย่างต่อคน: (1) commit แรกเป็น Spec (2) PR มี Handoff ส่วน 1–2 (3) ผู้เรียนอธิบายได้ว่าอ่าน diff อะไรไป
- ชั่วโมงนี้ใช้ Token สูง ตรวจ Usage ของ Key และ rate limit (429) ล่วงหน้า
- ถ้าผู้เรียนติดเกิน 10 นาที: เริ่ม Task ใหม่ → `/build.md` ใหม่ เป็นวิธีแก้อันดับแรกเสมอ
- ผู้เรียนที่ทำเสร็จก่อน → ให้ช่วยเพื่อน **ตรวจ Spec** (ตามประตูที่ 1) ไม่ใช่เขียนโค้ดให้
- สิ่งที่ต้องบันทึกลงแบบ Drill: เวลาแต่ละขั้น, รั้วชั้น 2 รั่วหรือไม่, Bot Comment ภายในกี่นาที
